<objective>
Create and validate the local monorepo foundation

<product_context>
The application presents one configurable Brazilian Portuguese
word, such as SAPO, on a single page.

The learner progresses through:
1. Individual letter sounds.
2. Combinations of those sounds.
3. The complete word.

The page highlights the letters involved in each step
and provides:
- Reference-audio playback.
- Microphone recording and stop controls.
- Playback of the learner's recording.
- A next-step action.
- A progress indicator.

The learner can listen to the reference, record an attempt,
replay both separately, and repeat before continuing.

Each sound combination has its own reference recording.
The lesson definition contains the target word, language,
ordered steps, highlighted letters, instructions,
and reference-audio locations.

Learner recordings remain temporarily in browser memory.

Relational storage holds lessons and their ordered steps.
DynamoDB stores anonymous practice-session progress.

An evaluation-service port initially uses a deterministic
success mock, explicitly identified as simulated.
It provides an extension point for a future AI integration.
</product_context>

<architecture>
FRONTEND
- React, Vite, and TypeScript.
- Material UI with responsive styling.
- English and Portuguese i18n scaffolding.
- Browser-compatible shared API contracts.

BACKEND
- Node.js, NestJS, and TypeScript.
- Domain: entities, value types, and business rules.
- Application: use cases and repository/service ports.
- Adapters: HTTP, persistence, and external-service adapters.
- Composition: Nest modules, injection tokens,
  and environment configuration.

DEPENDENCY DIRECTION
Domain and application code depend on application-owned
models and contracts.

Adapters implement those contracts.
Nest configuration connects ports to concrete adapters.

Keep controllers focused on HTTP transport and validation.
Keep use cases focused on application behavior.

RELATIONAL PERSISTENCE
- Local database: PostgreSQL in Docker.
- Data-access library: Prisma.
- Responsibility: lessons and ordered lesson steps.
- Future AWS target: Aurora PostgreSQL-Compatible.

NOSQL PERSISTENCE
- Local database: DynamoDB Local in Docker.
- Modeling library: Dynamoose.
- Responsibility: anonymous practice-session progress.
- Future AWS target: Amazon DynamoDB.

PERSISTENCE BOUNDARIES
Define a lesson-repository port and a progress-repository port
using application-owned types and meaningful operations.

Keep Prisma queries, generated types, and database mappings
inside the relational adapter.

Keep Dynamoose schemas, queries, and database mappings
inside the DynamoDB adapter.

Translate database results and errors into application-owned
contracts at the adapter boundary.

Each database owns its data. Session progress references
the lesson through its application-owned identifier.

SERVICE BOUNDARIES
Define an evaluation-service port and a mock adapter.
Use Nest dependency injection to select the implementation.

MONOREPO
Proposed tooling: pnpm workspaces and Turborepo.

Structure:
- apps/frontend
- apps/backend
- packages/shared

Shared packages contain browser-compatible API DTOs
and contracts. Persistence models belong to backend
adapters, and domain models belong to the backend core.
</architecture>
